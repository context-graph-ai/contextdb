# Performance result: find at 1,000,000 vectors on a 16-core desktop-class machine, 2026-11-26

## Promise

- Promise, in the product's words: "As a store grows, a vector search stays within the time the product promises". No figure promised.
- Counted test that guards it: `a_million_sightings_are_found_with_the_recorded_work_recall_and_length` (`v2/contextdb/tests/find_at_scale.rs`, release build, nightly) holds the vectors compared, the questions whose ten hold all of exact search's ten, and the data file's length at 1,000,000 generated sightings.

## Measurement

- Date: 2026-11-26 (02:07 to 03:25 UTC); revision measured: `672c10078a71d8b24a81ede80490bf979b0bcc79` (the script's header records one uncommitted file, a script fix made after the run began; the run used the committed script)
- Program and command: `v2/numbers.sh` with `NUMBERS_LARGE=1`, `IMPORT=dump-large`, `CAMERA_SECONDS=60`; lines `synthetic_1000000_*`, `sightings_1000000_*` and `sightings_1000000_contexts_{1,8,64}_*`
- Data: 1,000,000 generated vectors of 768 numbers (random near centroids, `synthetic`) and 1,000,000 generated sightings (tracks of ten whose appearance drifts), one partition each, loaded, sealed and grouped before searching; the last rows spread the sightings over 1, 8 and 64 contexts; 100 questions; recall is the share of the recorded true ten nearest found
- Passes and statistic: one run; p50 and p95 as the lines print them; threads: 1
- Resources: engine memory limit: 1,073,741,824 bytes in the find sessions (the `_session` lines), threads 1; enforced process memory: not recorded; cores available: 16 (32 threads)
- Storage: ext4; temporary-store class and cache state not recorded
- Comparison: previous figures are of `0c708a979e9eb5cbb1dca142f514edf96656711e` (sightings) and `7f150eed3afb284c2c02220431c3cb858635f361` (generated), 2026-11-14; not a controlled comparison
- Machine: AMD Ryzen 9 9955HX, 16 cores and 32 threads, 59 GiB of memory (a desktop-class build machine, to itself during the run; not a user's machine); operating system: Ubuntu 26.04.1, Linux 7.0; Rust toolchain: unknown; user's machine: no
- Settings that can change the result: build rustflags none; popcount counting; index reader limit 1,073,741,824 bytes; index threads 1; search mode as named in each row

## Limitations

- The p95 of the sightings searches is far above their p50 (indexed 30.673 against 0.966 ms); the tail is not explained here. Where the grouped index answers over all 64 contexts the p95 is 76.012 ms and exact is 231.734 ms.
- Exact search over 1,000,000 vectors is slower than on 2026-11-14 (generated 259.460 ms against 176.581 ms); the cause was not looked for.
- A single run on one machine; no timed figure is a promise. Recall is over 100 questions.
